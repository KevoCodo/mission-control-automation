# Automation readiness assessment

**Scope and evidence, 2026-10-21.** Source and documentation review of this isolated `KevoCodo/ai-delivery-lab` checkout only. No tests, builds, native programs, AO commands, GitHub calls, or runtime experiments were run for this assessment. “Tested” below means a test exists in source, not that this review reran it. The contents and current state of `KevoCodo/operis` issue #4, its branch protection, CI, and permissions were not fetched and are unverified.

## Executive summary

**Decision: no-go for an automatic Builder today.** The controller has useful fail-closed planning, identity, audit, PR/CI observation, and policy code. It does not have a trusted, executable launch path. `assignIssueWithAo` rejects every non-dry-run request before handoff; the concrete AO client also throws on live spawn. The Windows runner is a set of contracts, read-only inspections, and a disposable native harness whose runtime behavior has not been demonstrated. Authorization has no production issuer or verifier, and local STOP does not fence a process or an AO queue. A process exit, fixture receipt, local state transition, or passing TypeScript test cannot close these gaps.

The shortest path to **one** supervised Operis Builder is to keep Mission Control as the planner and sole local dispatch ledger, then add a narrow trusted Windows launch authority with OS-enforced worker isolation, authenticated one-use human grant, durable launch/fence evidence, and recoverable process-tree STOP. Prove those controls in an isolated, separately authorized environment before a one-issue pilot. Do not route launch through AO unless an independently reviewed AO protocol proves equivalent all-ingress admission, exact-ID lookup, and fencing; this checkout does not establish those guarantees. The React application is a fictional demonstration (`src/data/demoIssues.ts`, `src/App.tsx`) and is outside this milestone.

## Critical blockers to one automatic Builder

1. **No trusted launch authority or Codex execution adapter.** The current code cannot start one production Builder. A future adapter must invoke a pinned Codex binary with a reviewed, narrow argument contract, exact executable hash, controlled environment/handles, bounded prompt and output, and no generic worker shell or GitHub writer token. The trusted supervisor alone creates processes; Mission Control records and requests one dispatch.
2. **No enforced OS sandbox.** A dedicated low-privilege worker identity, NTFS ACL isolation, handle-based path and volume/file-ID checks, reparse/junction and swap defense, restricted token, network deny/allow policy, Job containment at creation, limits, and credential separation are unimplemented or unverified. A Job Object alone does not restrict filesystem or network access. The native harness is not production containment.
3. **No authenticated human grant at the effect boundary.** Grant issuance, actor authentication, signature/key trust, exact Operis #4/role/branch/workspace/base-commit/dispatch/generation/epoch scope, expiry, atomic single-use consumption, and immediate pre-start revalidation are missing. Approval in a UI, a CLI flag, or a state record is only a claim. Revocation must invalidate queued starts and credential use through the same trusted authority.
4. **No durable, all-ingress STOP.** Controller STOP is local. The trusted launcher must order a monotonic, durable fence against launch reservations and actual process creation; reject delayed/replayed starts after the barrier; revoke credentials and network capability for running work; terminate the entire Job/process tree; and independently prove descendants are contained. A termination request, parent PID disappearance, or local `FENCED` label is insufficient. If AO carries dispatch, its queue consumers and every worker-start ingress need the same provider-enforced ordering, not a controller-side check.
5. **No authoritative lifecycle evidence or safe recovery.** Launch, process identity (PID plus creation time and Job identity), workspace/executable identity, grant consumption, STOP barrier, exits, descendants, and bounded external effects need durable, ordered, authenticated receipts and an independent read path. State/audit currently have crash and power-loss gaps. A lost acknowledgement, provider restart, contradictory receipt, or uncertain descendant outcome must quarantine the exact dispatch without blind retry.
6. **No live GitHub/Operis facts or write boundary.** The checkout cannot authenticate issue #4, dependencies, base SHA, branch protection, CI, or PR state. For the first Builder, gather fresh read-only facts and keep credentials scoped; a separate, later gate is needed for branch push/PR creation. An issue-to-PR claim is premature until Tester, Reviewer, exact-head CI, bounded correction, and human merge/closure gates exist.

AO is **not** a shortcut for gates 2–4. If AO must be the launch transport, add an AO-specific prerequisite before gate 5: versioned provider contract and independent isolated conformance for authenticated submit/accept/reject, exact dispatch-ID lookup with complete retention, idempotency, all-ingress grant and epoch checks, durable retirement, and independent receipts. The current AO CLI/session adapter and prior source assessment do not verify these. Do not inspect or experiment with live AO to close this evidence gap.

## First automated Operis Builder acceptance test (future, separately authorized)

Use a fresh, independently read snapshot of `KevoCodo/operis` #4 and a human-approved AI Lead plan. The test starts **exactly one** Builder through the reviewed trusted supervisor in a dedicated, verified Operis worktree at an exact base SHA. The Builder receives only its scoped capabilities, creates a bounded result and local branch/worktree changes, and is not given issue/PR/merge authority. Record the grant, dispatch envelope, executable and workspace identity, OS containment, start, resource use, exit, descendants, and durable terminal receipt. A separate verifier must reconcile the same dispatch ID, digest, generation, epoch, and process tree from supervisor evidence after a restart; a local success message is insufficient.

**Pass:** no start before approval; exactly one authorized start; no workspace, credential, network, process-tree, or resource escape; authenticated ordered evidence and independent lookup agree; STOP/revocation test variants prevent a delayed start and leave no surviving descendant or usable credential; crash/lost-ack variants quarantine rather than retry; the resulting work is inspectable at the recorded base and branch. **Fail:** any ambiguity, missing evidence, stale binding, uncontained descendant, post-barrier start, duplicate launch, or inferred terminal state. This is a Builder safety test, **not** completion of Operis #4 or the full issue-to-PR workflow. PR/CI, independent Tester and Reviewer, corrections, merge, and issue/Epic closure each require later exact-head evidence and separately approved effects.

## Explicit limitations and prohibited actions until authorized

This assessment establishes source-level readiness only. The repository tests cited are unit/fixture evidence and were not executed here. No native containment, effective ACL/network policy, trusted grant, AO protocol, durable STOP, provider receipt, or Operis GitHub state was independently verified. The existing default-deny behavior remains the governing runtime boundary.

Do not launch a Builder or native fixture; enable a runtime experiment; call, inspect, reconcile, retry, or alter live AO or its daemon/sessions/transport/history; access the unresolved historical dispatch; change production flags or GitHub resources; begin Operis implementation; or modify/close AI Delivery Lab issues #13 or #23 under this assessment. Separate explicit authorization is required **before** disposable native/OS containment experiments, any AO protocol conformance work involving a running AO instance, GitHub writes, credential/ACL/network policy changes, or the Operis #4 pilot. Human approval of a plan does not itself authorize those experiments or a merge.
