# Gate 2B Experiment 00 build-provenance collector

**Status: source implementation only; Experiment 00 remains NO-GO.** This component launches no build, harness, fixture, worker or observer. It grants no build or runtime approval. The [Experiment 00 authorization package](BUILDER_WINDOWS_GATE2B_EXP00_AUTHORIZATION.md) and [Gate 2B plan](BUILDER_WINDOWS_GATE2B_EXPERIMENT_PLAN.md) still govern checkpoints B and C.

`tools/mission-control/src/exp00BuildProvenance.ts` exposes a local-consistency assessor and a closed snapshot entry point:

1. `captureExp00FileSnapshot(phase)` always fails with `TRUSTED_PATH_HANDLE_BOUNDARY_UNAVAILABLE` for every valid phase. It makes **no filesystem call**. Fixed paths may traverse unverified reparse-point ancestors; checking the final path with `lstat` cannot resolve that risk. Snapshot capture remains unavailable until a separately reviewed native path/handle verification boundary and protection model are implemented. There is no caller-supplied approval flag or bypass.
2. `assessExp00BuildProvenance(record)` strictly parses a version 1 record and checks local consistency. `createExp00BuildProvenanceCollector()` also rejects a repeated record ID within one in-memory instance. A new instance can accept the same record; no durable replay authority is claimed. Even a fully consistent record returns `UNVERIFIED`, `independentlyVerified:false`, `experiment00:'NO_GO'`, `productionAuthorized:false` and `executable:false`. Caller-provided hashes, process-event IDs and trace hashes are data, not independent proof.

## Version 1 manifest and evidence origin

The exact TypeScript interface is `Exp00BuildManifest`. It requires the reviewed 40-character source commit; the fixed disposable root and exact four source names; pre/post source file hashes, sizes, paths and file IDs; pre/post identities and versions for `cmd.exe`, `vcvars64.bat`, `cl.exe`, `link.exe`, and selected Windows SDK headers/libraries; process-event references; Windows SDK version; exact structured PowerShell, `cmd.exe`, two `cl.exe` and two `link.exe` executable/argument records for the default-disabled build; compiler working directory; `PATH`/`INCLUDE`/`LIB`/SDK/VC selection and empty compiler/linker option environment; complete sampled SDK include/library resolution lists; process-trace hash; both build-output and sealed-output hashes/identities; record ID and capture/build timestamps. The `cmd.exe /c` argument must equal the fixed command assembled by the reviewed build script, including both compilation segments in order. The linker argv template is deliberately narrow; it has **not** been verified against a real build. If the actual linker argv differs, the record is rejected until a separately reviewed contract revision. These are **claimed** invocations, not authenticated process observations. Actual process commands and transitive inputs still require independent raw trace review.

The assessor rejects missing fields, extra fields, wrong paths, duplicate allowlist entries, changed source/toolchain input bytes or identity, mismatched output bytes, contradictory times or file IDs, absent process attribution, unrelated executables, arguments or shell wrappers, and a runtime-enabled build command. It rejects any `@` response-file reference in reported arguments or the shell command, and any nonempty response-file list. Response-file content capture is not implemented; a path alone cannot account for its contents. The SDK resolution lists must contain each sampled header/library exactly once and cannot contain unsampled paths. That comparison cannot detect inputs omitted from **both** the samples and the list; independent include/library tracing remains required.

| Value | What this component can establish | What remains independent |
| --- | --- | --- |
| Snapshot entry point | No file opens; valid phases fail closed | Trusted native path/handle boundary, native file ID, reparse and ACL protection, continued protection and Git-blob comparison |
| Complete manifest | Exact schema and local consistency of supplied values | Actual compiler/linker process identity, full input resolution, absence of omitted dependencies, trustworthy clocks and record custody |
| Process trace reference | A syntactically valid reference and digest | Trace origin, event coverage/loss and correspondence to the actual build |
| `UNVERIFIED` verdict | No local contradiction detected | All checkpoint B evidence review and checkpoint C authorization |

## Future authorized use

Before a future authorized build can use snapshot capture, a separate implementation and review must establish handle-based verification of every path component and the opened file's identity, effective replacement protection and a safe reader boundary. This milestone implements none of those. After that boundary, a separately reviewed staging design and **human approval B** would still be required before any source copying or native build. The custodian would have to gather pre/post source, toolchain and SDK identities, actual process images and arguments, include/library resolution, ACL evidence and sealed-output identity through independently reviewed methods, then retain the version 1 manifest alongside raw records. The assessor can reject inconsistent submissions and return a normalized manifest for review; it cannot authenticate the submitted observations. Only after independent evidence review may separate human approval C be considered. No result here authorizes B, C or a run.

The current build script emits neither the full manifest nor authenticated tool/process observations. No host path protection, complete observer, native build, fixture execution or cleanup has been verified by this source milestone. A complete-looking manifest is insufficient if independent observation or protection is missing.
