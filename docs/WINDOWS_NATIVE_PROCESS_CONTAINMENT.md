## Job and creation design

`disposable_job_probe.cpp` retains explicit RAII Job Object ownership, non-inheritable creation, `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, active process limit one, and limit readback. Its dormant `AssignProcessToJobObject` method remains for source review; the harness does not use assignment after creation. The harness checks the job handle inheritance flag, configures `PROC_THREAD_ATTRIBUTE_JOB_LIST`, and calls `CreateProcessW` with `EXTENDED_STARTUPINFO_PRESENT | CREATE_SUSPENDED | CREATE_NO_WINDOW` and `bInheritHandles=FALSE`. It does not request breakaway. It queries membership before resuming the primary thread. Creation-time job list assignment is the proposed containment-before-execution boundary. **CREATE_SUSPENDED followed by assignment is not treated as atomic containment.** If the attribute is unavailable, creation or nested-job assignment fails, or membership cannot be confirmed, the thread is never resumed. The harness reports a fail-closed result.

The harness waits for the fixture process handle, reads its exit code, requests job termination if normal exit was not observed, waits again, and reports close failures. `TerminateJobObject` success is only a request. A timeout, failed wait, failed handle close, or missing process observation does not become verified termination. A supervisor crash, inherited or duplicated job handle outside this program, or a failed close can leave cleanup uncertain. The source cannot prove descendants or post-crash cleanup. The one-process limit is configured and read back, but its enforcement has not been tested. No memory, CPU, filesystem, network, credential, restricted-token, or worker identity restriction is implemented or claimed. The current interactive token would be used for a future disposable run.

Microsoft documents `PROC_THREAD_ATTRIBUTE_JOB_LIST` as a creation attribute supported on Windows 10 and Windows Server 2016 or later, and nested jobs as conditional on a valid hierarchy. See [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), and [Nested Jobs](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs). These API descriptions support the proposed ordering, but this build alone does not establish the behavior of this OS, host job hierarchy, or compiled binaries. There is no fallback to post-creation assignment or breakaway.
