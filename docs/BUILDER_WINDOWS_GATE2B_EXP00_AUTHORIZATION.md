## Independent no-child observer: review gate

The proposed practical observer is a **pre-existing, already configured** Sysmon Process Create (Event ID 1) stream in `Microsoft-Windows-Sysmon/Operational`, read by a separate observer identity with only the effective log-read rights it needs. Microsoft's [Sysmon event reference](https://learn.microsoft.com/en-us/windows/security/operating-system-security/sysmon/sysmon-events) describes Process Create records with command line, parent process and process GUID. This is a candidate, **not** an assertion that Sysmon is installed, configured for all process starts, complete, or trusted on the selected host. Installing or reconfiguring it, changing audit policy, using elevation, or expanding log rights is outside this package. If it is absent or filtered, this observer design is NO-GO pending a new reviewed package. A pre-existing Windows Security 4688 process-creation audit may corroborate it if already enabled; it is not a substitute without its own coverage review. [Microsoft's audit documentation](https://learn.microsoft.com/en-us/windows/security/threat-protection/auditing/audit-process-creation) states that 4688 depends on Audit Process Creation being enabled.

Before a run, an independent reviewer must verify observer binary/service version and hash, actual configuration and filters, service health, log retention/size, access rights and privileges, clock, event latency and loss/error reporting. The observer starts or bookmarks **before** harness creation and covers harness launch, its full lifetime, a reviewed post-exit delivery margin and cleanup inventory. Record start/end UTC and monotonic times, initial/final EventRecordID or equivalent bookmark, raw EVTX export and a SHA-256 of the export. Preserve a machine-readable event table with provider/channel, event ID/record ID, UTC timestamp, ProcessGuid, ProcessId, image, command line, ParentProcessGuid/ParentProcessId, user SID and parser version. Record Sysmon errors (including Event ID 255 if present), service interruptions, log clear/rollover and any dropped-event signal. Correlate the observed harness ProcessGuid/PID and creation time to the independently recorded invocation and staged image hash. Search the complete bounded stream for the exact fixture image/path/hash, both as a child of that harness and anywhere else under the disposable test identity/root. A pre/post process snapshot adds cleanup context but cannot rule out a 250 ms child by itself.

The reviewer must show that this stream covered **all** relevant process creation on the host during the window, with no exclusion that could hide the harness or fixture, no overwritten records, no unexplained gap and a justified delivery bound. Observing the harness's own create record is a useful health check but alone does not prove completeness. If event loss is not measurable or bounded, or if the stream cannot distinguish a missing child from missing telemetry, result is **INCONCLUSIVE / NO-GO**, even when the harness prints the expected denial. Sysmon's service may require elevated installation, but this package permits only an already provisioned observer and an unelevated read-only observer identity. The reviewer must assess whether collection or another security product alters process creation; any meaningful interference is NO-GO. No ordering or containment guarantee for experiments 01–02 is inferred from this observer.
