# Windows worker filesystem inspection (S2B-2A)

S2B-2A adds read-only local inspection. It does not enforce a sandbox or authorize execution. `inspectWindowsWorkspace` checks a strict drive-absolute path, reads each lexical component with Node `lstat`, checks the final target with `stat`, and obtains Node `realpath`. It reports missing, inaccessible, non-directory, canonical mismatch, and link or junction observations. Node `dev` and `ino` are recorded only when nonzero. These are OS metadata observations, not authenticated Windows volume serial and file IDs. An ordinary `lstat` directory is labelled `UNKNOWN_REPARSE_STATUS` because Node cannot exclude every reparse tag.

UNC, device, relative, traversal, alternate data stream, reserved-name, and trailing-dot or trailing-space claims are rejected before inspection. String comparison is only a rejection filter. It is not filesystem containment proof. A path can change between `lstat`, `stat`, and `realpath`; those calls do not share a protected handle. Junction, symlink, other reparse, and ancestor substitution races remain possible. No symlink or junction is created by these tests, so native behavior is not experimentally validated here.

The `NativeWindowsAclInspection` interface marks a future read-only native boundary. Current Node APIs do not establish effective access of a separate low-privilege SID, account for inherited deny/allow ACEs, privileges, group membership, integrity levels, or prove denial outside one workspace. `icacls` output is not parsed. ACL enforcement is always `UNVERIFIED`; exclusive worker access is never claimed.

`assessWindowsWorkspaceReadiness` invokes the OS inspection itself and separately runs the S2B-1 claim assessor. It never accepts a caller-supplied observation as trusted evidence. Caller fields such as `trusted`, `verified`, `sandboxReady`, or `issuer` do not authenticate a provider. The typed record is explicitly `NODE_OS_OBSERVATION` with `authenticity: UNVERIFIED`. A native issuer must later bind a versioned receipt to verified component identity, execution and dispatch IDs, worker SID, volume/file IDs, workspace generation, fencing epoch, protected handle, and a non-replayable sequence or challenge. The verifier must authenticate that receipt outside caller-controlled fields.

The assessment reports distinct workspace, metadata identity, reparse, ACL, native provider, network, process containment, and STOP synchronization gaps. It always returns `productionAuthorized: false` and `executable: false`. The S2B-1 structural claim result is included for context only. A caller's complete fixture does not become authority.

`assessObservationFreshness` invalidates a snapshot on age or changed workspace root, worker ID, or generation. It is a denial check, never proof. Future launch must repeat checks while holding protected OS handles, bind ACL and path policy to the same file and volume identity, and synchronize the checked generation and STOP fence with the start gate. A previously successful preflight cannot authorize later launch. Handle-based final-path resolution, `GetFileInformationByHandleEx` file/volume identity, reparse-tag inspection, race-resistant component traversal, and an authenticated native receipt are required for S2B-2B. Network isolation, process tree containment, credentials, executable verification, and durable STOP barrier also require independent evidence.

No-go conditions include invalid or inaccessible workspace, path ambiguity, unknown reparse status, missing native identity or ACL evidence, absent network or process containment, missing STOP synchronization, stale generation, unverifiable receipt provenance, and unresolved AO delivery. This module reads filesystem metadata only. It launches no process, writes no dispatch or recovery state, and changes no ACL.

Tests use disposable directories under `E:\AI-Development\temp`. Inaccessible directories cannot safely be produced without changing ACLs, so the implementation maps OS `EACCES` and `EPERM` to `WORKSPACE_INACCESSIBLE` without a live ACL fixture. Native reparse and junction behavior is untested. The final test, build, audit, and diff-check results are recorded in the completion report.
